01 / THE IDEA

AI that does not begin again every session.

Corvus started from a simple product question: what would a personal AI look like if the same person used it for months or years, on hardware they already own?

The system treats conversation history as durable evidence rather than disposable prompt text. Raw experience remains canonical; retrieval, interpretation, and higher-level memory can evolve without rewriting what actually happened.

CORE PRINCIPLE

Store all experience. Spend intelligence selectively.

02 / MEMORY SYSTEM

Evidence first. Interpretation stays rebuildable.

Corvus separates what the user actually said from what the system currently understands. That boundary keeps long-term memory inspectable, correctable, and safer to evolve.

01 / CANONICAL

Evidence Log

SQLite-backed raw conversation evidence. Durable, chronological, and never replaced by a derived summary.

02 / ACTIVE

Working Context

Recent conversation plus targeted recall assembled for the current turn.

03 / DERIVED

Materialized Memory

Assertions, relations, temporal state, and future derived views remain correctable and rebuildable.

Evidence Recall

Answers: “What did the user actually say?” Sparse BM25 and multilingual dense retrieval are fused, then hydrated back from canonical SQLite records.

Knowledge Recall

Designed for the evolving question: “What does Corvus currently understand?” Derived memory never replaces the underlying evidence.

03 / LOCAL RUNTIME

Built for hardware people actually own.

The current deployment shares one local model runtime across Private and Demo Corvus. Conversation state, authentication trust, and canonical memory remain isolated even while the expensive inference layer is reused.

04 / DEPLOYMENT

One product. Two isolated worlds.

Corvus is deployed twice from the same codebase: a private long-term instance and a clean recruiter-facing demo. They share the local model runtime, but not credentials, authentication keys, application processes, or canonical data.

PRIVATE

Private Corvus

A persistent personal instance with its own FoxGate realm and canonical memory.

  • Independent auth realm
  • Independent API / Web
  • Private canonical SQLite + LanceDB
  • Hidden from portfolio

Same product. Same model runtime. Separate authentication trust and canonical memory.

05 / VALIDATION

Designed to survive outside the development session.

The deployment was accepted through real browser flows and a full-host reboot rather than only local unit checks. Canonical data integrity and fail-closed access were verified after recovery.

✓Persistent SQLite evidence log across sessions
✓Sparse + dense hybrid evidence retrieval
✓Cross-session recall after fresh process restart
✓Physical Private / Demo canonical-data isolation
✓Secure, HttpOnly, SameSite session cookies
✓Public routes fail closed when unauthenticated
✓Loopback-only application origins
✓Automatic recovery after full-host reboot
